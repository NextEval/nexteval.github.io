Installation

Use Python 3.10 or later. These examples target NextEval Solver 1.0.0, whose only runtime dependency is NumPy. The built-in provider clients need nothing else; no Codex or Claude Code installation is needed for this route.

The package is not yet published on a public package index. Install it from the source directory or wheel file you were given; replace ./nexteval below with its path.

python3 -m venv .venv
source .venv/bin/activate
python -m pip install ./nexteval
python -c "import nexteval; print(nexteval.__version__)"

The last command prints 1.0.0. On Windows PowerShell, create the environment with py -m venv .venv and activate it with .venv\Scripts\Activate.ps1. The remaining Python commands are the same.

Model and harness

Solver Python API
solve and minimize accept your objective, starting point and numerical options.
Model provider API
The external service that returns model responses. A provider client owns its endpoint, credentials and wire format.
Harness
The session loop that connects model responses to numerical tools. Use the built-in ToolCallingTaskRunner, or supply an external runner.
Bench task protocol
Separate task, participant and evaluation records for comparisons. See NextEval Bench; it is not required to optimize your own function.

With execution_mode="task" and no custom runner, NextEval constructs the built-in harness. runner_options configures that harness. With runner=..., configure the supplied object directly: it owns model selection, authentication and thinking settings. There is no universal harness="codex" or harness="cc" argument.

OpenAI-compatible transport is not Codex. Anthropic-compatible transport is not Claude Code. Changing only a provider URL does not change the harness.

Model provider setup

Choose a tool-calling endpoint you are authorized to use. Supply credentials through your local environment or credential manager. All values below are placeholders; the website neither receives credentials nor sends model requests.

OpenAI-compatible client

export NEXTEVAL_OPENAI_BASE_URL="https://your-provider.example/v1"
export NEXTEVAL_OPENAI_MODEL="your-model-id"
export NEXTEVAL_OPENAI_API_KEY="<provided-by-your-credential-manager>"

OpenAICompatClient() uses Chat Completions with tool calls. An endpoint that only supports another protocol is not interchangeable. Provider-specific reasoning options belong to this client, not to maxfev. Check the selected model's documentation before using extra_body or changing max_tokens_field.

Anthropic-compatible client

export ANTHROPIC_BASE_URL="https://your-provider.example/v1"
export ANTHROPIC_MODEL="your-model-id"
export ANTHROPIC_AUTH_TOKEN="<provided-by-your-credential-manager>"

Use AnthropicCompatClient(). The shortcut model="env" also selects this client; it does not automatically detect your provider. On PowerShell, use $env:VARIABLE="value" instead of export.

Thinking settings and credentials

Thinking options are provider- and model-specific. A missing field may mean the provider's default, not thinking off. Record both the requested setting and what the provider reports in its responses before comparing runs.

Use a key that the provider issues for programmatic API access, with an endpoint and authentication method that the provider documents for it. A command-line tool's login session is not an API key; do not copy login tokens into a generic API client.

First run

This two-dimensional objective uses the same fun and x0 for every harness. Only the harness changes. Running it with a real provider can incur charges.

import numpy as np
from nexteval import OpenAICompatClient, minimize

fun = lambda x: float(x @ x)
x0 = np.array([-1.2, 1.0])

result = minimize(
    fun, x0,
    model=OpenAICompatClient(),
    toolset="core-v04",
    options={
        "execution_mode": "task",
        "maxfev": 80,
        "model_call_limit": 60,
        "runner_options": {"max_tokens": 4096},
        "seed": 7,
        "trace": "trajectory",
        "run_dir": "runs",
    },
)
print(result.x, result.fun, result.nfev)
print(result.status, result.message, result.trace_path)

Download optimize.py includes this objective and Rosenbrock, a curved-valley example. Both start at [-1.2, 1.0]. After configuring a provider, run either example:

python optimize.py --problem sphere --provider openai --maxfev 80
python optimize.py --problem rosenbrock --provider openai --maxfev 100

For the Anthropic-compatible connection, use --provider anthropic. No fixed final value is promised: the model's choices and stopping decision can vary. Complete arguments and return fields are in the Solver Python API reference.

External agent sessions

Not bundled with the Solver. NextEval Solver 1.0.0 does not include runners for agent command-line tools such as Codex or Claude Code. To let such an agent drive a complete session, supply your own runner with runner=.... The agent then works with the same numerical tools, budget and evaluation records as the built-in harness.

run(task, gateway)
Required. task is a serializable description of the problem: dimension, x0, budgets, instructions and the tool definitions in task["tools"]. Return a mapping such as {"stop": "completed"} when the session ends.
gateway.call(name, arguments)
Runs one tool and returns a JSON-serializable result. The Solver validates each call, runs the objective evaluations it requires, records them and enforces the budget. gateway.done becomes true when the session has ended.
gateway.begin_turn()
Optional. Call it before forwarding the tool calls of each agent reply. At most one sampling action then runs per reply; further sampling actions in the same reply are deferred without spending budget.
describe()
Optional. Returns metadata about the runner, such as a harness_id.

This scripted runner shows the contract without a model or credentials. Save it next to optimize.py and run it:

from optimize import run


class ScriptedRunner:
    """Stands in for an agent: two poll points, then finalize."""

    def describe(self):
        return {"harness_id": "scripted-example"}

    def run(self, task, gateway):
        # An agent harness exposes task["tools"] to the agent and forwards
        # each tool call it makes through gateway.call(name, arguments).
        gateway.call("execute_action", {
            "tool": "poll_set",
            "parameters": {"basis": "maximal_positive", "count": 2},
            "purpose": "geometry",
            "rationale": "scripted example",
        })
        gateway.call("finalize", {"reason": "scripted example complete"})
        return {"stop": "completed"}


result = run(problem="sphere", runner=ScriptedRunner(), maxfev=80)
print(result.nfev, result.fun, result.model_request_count)

The first printed value is 3: the starting point and the two poll points. For a real agent, replace the scripted calls with a loop that starts the agent, exposes task["tools"] to it (for example as function tools or through an MCP server), forwards each tool call through gateway.call, and returns when the agent calls finalize or gateway.done is true.

The agent tool then owns its model selection, authentication and thinking settings. The built-in model meter does not see its requests, so result.model_request_count is None; set request and token limits in the agent's own configuration. Check what the agent reports about these settings: a zero exit code alone does not show that it ran as configured.

Use a new runner and run directory for each episode. Continuing a session must keep the same gateway and budget; it does not permit restarting the optimization with a fresh budget.

Authenticate the agent tool only in ways its provider supports for your use. Codex supports ChatGPT sign-in and API-key authentication; see the official Codex authentication page. Anthropic's Agent SDK documentation does not generally permit third-party products to offer Claude.ai login or rate limits without prior approval. Do not assume that a personal command-line login can be reused by an application.

Budgets and limits

maxfev
Actual objective calls, including the initial point and failed calls. Cached values and read-only tools consume no new evaluations.
model_call_limit
model_token_limit
Separate limits on requests through the built-in model meter. Requests made inside an external runner are not visible to this meter; set that runner's own request and token limits.
runner_options
Built-in harness settings, such as per-request max_tokens, compaction and retries. Do not pass this option with an explicitly supplied runner.
task_max_tool_calls
A separate gateway-call ceiling. One numerical tool call may perform several objective evaluations; a read may perform none.
wall_time_limit_s
A cooperative deadline, not a forced kill of a blocked objective or external process. Use a process supervisor when a hard deadline is required.

A finite evaluation budget does not guarantee that it will all be used. Agent finalization, invalid evaluations, transport failures or other resource limits may end the session first. Compare completion quality as well as the final objective.

Results and traces

result.x and result.fun identify the best valid recorded point. Inspect nfev, status, message, completion_quality and comparable_under_budget. An incumbent value is not proof of a healthy model session or a valid benchmark trial.

runs/<run_id>/
  manifest.json
  summary.json
  events.jsonl

trace="trajectory" enables this persistent Solver Trace, and result.trace_path gives the actual directory. trace="summary" omits the event stream; trace="off" disables the persistent trace. Diagnostic log_level is separate from trace capture.

The Solver owns the evaluation records. An external agent's own transcript is a separate artifact, not a replacement for them. Before sharing raw traces, check them for sensitive objective or model content.

Troubleshooting

Missing configuration
Check the environment variable names for the client you constructed. model="env" is Anthropic-compatible, not provider autodetection.
Authentication and usage limits
Check the endpoint, your access and the credential locally. A revoked credential is different from an exhausted usage limit. Do not print tokens or repeatedly retry a revoked credential.
No usable tool call
Confirm tool-calling support and compatible request fields. Token truncation, thinking defaults and transport mismatches can stop a session before the evaluation budget is spent.
External runner
nexteval does not include Codex or Claude Code runners. Supply your own runner object; see External agent sessions.
Invalid objective
Check that fun(x) returns a scalar and that x0 is finite and one-dimensional. Failed objective calls still count.

Validation status

The downloadable example and the scripted runner example are checked offline against local scripted responses; the scope and results are in the guide checks.

No paid provider run was made for this guide. The offline checks cover installation, request serialization, tool responses, evaluation budgets and trace files. They do not show provider access, provider compatibility, model quality, or that any particular agent tool works as a runner.
