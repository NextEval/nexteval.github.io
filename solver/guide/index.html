Installation

Use Python 3.10 or later. These examples target NextEval 1.0.0 at cb58fd7. The built-in provider clients need only the package's NumPy dependency; no Codex or Claude Code installation is needed for this route.

python3 -m venv .venv
source .venv/bin/activate
python -m pip install \
  "git+https://github.com/NextEval/nexteval.git@cb58fd74901de2476fe15b60ee4cfc993ca04095"
python -c "import nexteval; print(nexteval.__version__)"

On Windows PowerShell, create the environment with py -m venv .venv and activate it with .venv\Scripts\Activate.ps1. The remaining Python commands are the same. The clean-environment checks below were run on macOS, not Windows.

Model and harness

Solver Python API
solve and minimize accept your objective, starting point and numerical options.
Model provider API
The external service that returns model responses. A provider client owns its endpoint, credentials and wire format.
Harness
The session controller that connects model responses to numerical tools. Use the built-in ToolCallingTaskRunner, or supply an external runner.
Bench task protocol
Separate task, participant and evaluation records for comparisons. See NextEval Bench; it is not required to optimize your own function.

With execution_mode="task" and no custom runner, NextEval constructs the built-in harness. runner_options configures that harness. With runner=..., configure the supplied object directly: it owns model selection, authentication and thinking settings. There is no universal harness="codex" or harness="cc" argument.

OpenAI-compatible transport is not Codex. Anthropic-compatible transport is not Claude Code. Changing only a provider URL does not change the harness.

Model provider setup

Choose a tool-calling endpoint you are authorized to use. Supply credentials through your local environment or credential manager. All values below are placeholders; the website neither receives credentials nor sends model requests.

OpenAI-compatible client

export NEXTEVAL_OPENAI_BASE_URL="https://your-provider.example/v1"
export NEXTEVAL_OPENAI_MODEL="your-model-id"
export NEXTEVAL_OPENAI_API_KEY="<provided-by-your-credential-manager>"

OpenAICompatClient() uses Chat Completions with tool calls. An endpoint that only supports another protocol is not interchangeable. Provider-specific reasoning options belong to this client, not to maxfev. Check the selected model's documentation before using extra_body or changing max_tokens_field.

Anthropic-compatible client

export ANTHROPIC_BASE_URL="https://your-provider.example/v1"
export ANTHROPIC_MODEL="your-model-id"
export ANTHROPIC_AUTH_TOKEN="<provided-by-your-credential-manager>"

Use AnthropicCompatClient(). The shortcut model="env" also selects this client; it does not automatically detect your provider. On PowerShell, use $env:VARIABLE="value" instead of export.

Thinking and coding plans

Thinking options are provider- and model-specific. A missing field may mean the provider's default, not thinking off. Record both the requested setting and the available response receipts before comparing runs.

A coding-plan API credential is not the same as a CLI login session. Use only the endpoint and authentication method supported by your plan and adapter; do not copy login tokens into a generic API client. The historical adapters below have fixed routes, not interchangeable subscription access.

First run

This two-dimensional objective uses the same fun and x0 for every harness. Only the controller changes. Running it with a real provider can incur charges.

import numpy as np
from nexteval import OpenAICompatClient, minimize

fun = lambda x: float(x @ x)
x0 = np.array([-1.2, 1.0])

result = minimize(
    fun, x0,
    model=OpenAICompatClient(),
    toolset="core-v04",
    options={
        "execution_mode": "task",
        "maxfev": 80,
        "model_call_limit": 60,
        "runner_options": {"max_tokens": 4096},
        "seed": 7,
        "trace": "trajectory",
        "run_dir": "runs",
    },
)
print(result.x, result.fun, result.nfev)
print(result.status, result.message, result.trace_path)

Download optimize.py includes this objective and Rosenbrock, a curved-valley example. Both start at [-1.2, 1.0]. After configuring a provider, run either example:

python optimize.py --problem sphere --provider openai --maxfev 80
python optimize.py --problem rosenbrock --provider openai --maxfev 100

For the Anthropic-compatible connection, use --provider anthropic. No fixed final value is promised: the model's choices and stopping decision can vary. Complete arguments and return fields are in the Solver Python API reference.

Codex sessions

Research integration, not a bundled Solver adapter. A Codex task runner keeps a complete CLI conversation connected to the same numerical gateway. The public Solver supports runner=..., but does not export a general-purpose CodexRunner.

The accessible-to-collaborators research adapter guide documents benchmarks.codex_qwen.CodexQwenRunner. It requires access to that private repository, codex on PATH, and zstd if the CLI compresses requests. The recorded compatibility environment used Python 3.12, Codex CLI 0.153.4 and Solver 60f4bb0. Compatibility with Solver cb58fd7 is not yet live-validated.

This adapter fixes Qwen 3.8 Flash on the DashScope coding endpoint and reads DASHSCOPE_API_KEY. Its reasoning_effort accepts none, low or medium; none requests thinking off. It creates a private temporary Codex home, rather than automatically using your normal ChatGPT login.

# Requires the pinned research checkout on PYTHONPATH.
# Integration pattern; not a current-version live verification.
from pathlib import Path
from benchmarks.codex_qwen import CodexQwenRunner
from optimize import run

runner = CodexQwenRunner(
    Path("local-runs/new-episode/codex"),
    reasoning_effort="none",
    max_requests=60,
    max_resumes=2,
)
result = run(problem="sphere", runner=runner, maxfev=80)

Use a new artifact directory and runner for each episode. Same-session continuation must retain the gateway, budget and ledger; it is not permission to restart optimization with a fresh budget.

For OpenAI models, Codex itself supports ChatGPT sign-in and API-key authentication; see official Codex authentication. That does not make the fixed Qwen adapter a GPT adapter. The archived GPT runner is experiment-specific, including model registration, reasoning and Windows paths; no generic install-and-run recipe is claimed here.

Claude Code sessions

Research integration, not a bundled Solver adapter. The historical complete-session route uses the Claude Agent SDK and exposes NextEval's task tools over MCP. It is different from a one-shot subprocess invoked once per solver decision.

The private research frozen ClaudeCodeRunner fixes the Volcano coding endpoint and accepts only its registered DeepSeek V4 Flash/Pro models. It reads ANTHROPIC_AUTH_TOKEN. The archived requirements include claude-agent-sdk==0.2.152, httpx2==2.12.0 and Solver 60f4bb0. Keep this historical environment separate from the current installation.

# Requires the reviewed research adapter and its dependencies.
# Integration pattern; not a current-version live verification.
from pathlib import Path
from claude_runner import ClaudeCodeRunner
from optimize import run

runner = ClaudeCodeRunner(
    Path("local-runs/new-episode/claude-code"),
    model="deepseek-v4-flash",
    timeout_s=1800,
)
result = run(problem="sphere", runner=runner, maxfev=80)

This adapter requests thinking off and uses a compatibility proxy to send the explicit disabled field. Check runner_report, model receipts and thinking_disabled_effective; process exit zero alone is insufficient. This is not a general Claude model or Claude subscription example, and it has not been live-validated against cb58fd7 here.

Authentication must also comply with the provider's supported SDK route. Anthropic's Agent SDK documentation does not generally permit third-party products to offer claude.ai login or rate limits without prior approval. Do not assume a personal CLI login can be reused by an SDK application.

Budgets and limits

maxfev
Actual objective calls, including the initial point and failed calls. Cached values and read-only tools consume no new evaluations.
model_call_limit
model_token_limit
Separate limits on requests through the built-in model meter. External runner internals may not be visible; configure and audit their own request/token limits.
runner_options
Built-in harness settings, such as per-request max_tokens, compaction and retries. Do not pass this option with an explicitly supplied runner.
task_max_tool_calls
A separate gateway-call ceiling. One numerical tool call may perform several objective evaluations; a read may perform none.
wall_time_limit_s
A cooperative deadline, not a forced kill of a blocked objective or external process. Use a process supervisor when a hard deadline is required.

A finite evaluation budget does not guarantee that it will all be used. Agent finalization, invalid evaluations, transport failures or other resource limits may end the session first. Compare completion quality as well as the final objective.

Results and traces

result.x and result.fun identify the best valid recorded point. Inspect nfev, status, message, completion_quality and comparable_under_budget. An incumbent value is not proof of a healthy model session or a valid benchmark trial.

runs/<run_id>/
  manifest.json
  summary.json
  events.jsonl

trace="trajectory" enables this persistent Solver Trace, and result.trace_path gives the actual directory. trace="summary" omits the event stream; trace="off" disables persistent evidence. Diagnostic log_level is separate from trace capture.

The kernel owns evaluation records. An external agent transcript or Harbor/ATIF trajectory is a separate artifact, not a replacement for the ledger. Keep raw traces private until reviewed for sensitive objective/model content. See the Solver Trace contract.

Troubleshooting

Missing configuration
Check the environment variable names for the client you constructed. model="env" is Anthropic-compatible, not provider autodetection.
Authentication / quota
Check endpoint, account access and credential validity locally. A revoked login is not exhausted quota. Do not print tokens or repeatedly retry a revoked credential.
No usable tool call
Confirm tool-calling support and compatible request fields. Token truncation, thinking defaults and transport mismatches can stop a session before the evaluation budget is spent.
External runner import
Codex/Claude Code research adapters are not exported by nexteval. Repository access, adapter dependencies and compatible CLI/SDK versions are separate prerequisites.
Invalid objective
Check that fun(x) returns a scalar and that x0 is finite and one-dimensional. Failed objective calls still count.
