## Slim site release

The website serves only a slim projection of this full view. `node scripts/results-storage/prepare-site.mjs`:

1. builds and verifies the full view in `dist/results/` from the pinned artifact (`prepare-public-results.mjs`); every file hash is checked;
2. runs `site_projection.py`, which keeps an explicit field allowlist, drops the four retired tiers, shows the pair scores of `data/pair/` as the task scores (COBYQA = 0.5), omits the joint scores and joint profiles and copies every kept value unchanged;
3. writes `dist/site/{MANIFEST.json,results/,results.tar.gz}` (deterministic) and, when `site-release.pin.json` is present, checks the MANIFEST and tarball against the pin.

The slim bundle has the result views only: matrix, profiles (pairwise performance and data profiles versus COBYQA), Pareto (cost, tokens, release date), agent pages (with log-ratio profiles), task histories and coverage, and methodology. It ships no evidence, sources, limitations, archive or attempt identities, hashes, download links, `usage-estimates.html`, ten-repeat archive, historical-assisted data or node check scripts. The UI sources that differ from the full view are in `scripts/site-ui/` (`app.mjs`, `model.mjs`, `profile-figures.mjs`, `logratio.mjs`, `pair.css`, the `/bench/results/` redirect `index.html`).

`site-release.pin.json` pins the current release: the Pages GitHub release asset (the tarball, public, no token needed) and the private HF dataset `NextEval/nexteval-bench-web` (`releases/<tag>/`, HF tag `<tag>`). The full view stays the validation target of the other tests; `test-site-projection.mjs` checks the allowlist, value equality with the full view, displayed counts 43/43/43/43 and determinism.

Full artifact access: once the public full-view release is a draft, run `node scripts/results-storage/fetch-full-artifact.mjs` with GitHub credentials that can read draft releases. It downloads the pinned asset id into `.cache/full-artifact/` and checks its sha256; `prepare-public-results.mjs` then uses that copy offline. The same bytes are in the private HF dataset `NextEval/nexteval-bench-data` at the pinned revision.
